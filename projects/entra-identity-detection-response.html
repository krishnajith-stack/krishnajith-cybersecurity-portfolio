Identity Security & Detection Portfolio Lab Project

Microsoft Entra ID Attack Detection & Response

A practical identity-security lab showing how suspicious sign-in and privileged-access activity can be detected, investigated and responded to using Microsoft Entra ID, Microsoft Sentinel and KQL.

Entra IDMicrosoft SentinelKQLConditional AccessMFAMITRE ATT&CK
Lab scope: This portfolio project uses synthetic scenarios and lab-oriented detection logic. It does not contain production tenant data or imply that these exact events occurred in a client environment.

Objective

Demonstrate an end-to-end identity detection workflow: collect sign-in telemetry, identify abnormal behavior, investigate context, create Sentinel detections, map activity to ATT&CK and define containment/remediation actions.

Architecture

Entra ID sign-in and audit telemetry → Log Analytics → Microsoft Sentinel → KQL analytics → Alert / Incident → Entity investigation → Response → Conditional Access / account remediation.

Attack Scenarios

1. Password SprayMultiple users targeted from the same source with repeated authentication failures followed by a successful sign-in.
2. Repeated Failed Sign-insHigh-volume failures against a single identity, indicating credential guessing or automated abuse.
3. Suspicious Privileged ActivityUnexpected role assignment, role activation or sensitive directory change involving privileged accounts.
4. Risky / Unusual Sign-in PatternSign-in behavior with unusual location, device, application, IP reputation or authentication characteristics requiring analyst validation.
5. MFA AnomalyAuthentication events suggesting repeated MFA challenges, unusual failure patterns or activity requiring user confirmation and session review.

Example KQL — Password Spray Pattern

Illustrative query for identifying one source IP generating failed sign-ins across multiple users within a short window.

SigninLogs | where TimeGenerated > ago(1h) | where ResultType != 0 | summarize FailedAttempts=count(), TargetUsers=dcount(UserPrincipalName), Users=make_set(UserPrincipalName, 20) by IPAddress, bin(TimeGenerated, 15m) | where FailedAttempts >= 10 and TargetUsers >= 5 | order by FailedAttempts desc

Investigation Workflow

  1. Validate alert and affected identity.
  2. Review sign-in timeline and authentication result.
  3. Check source IP, device, application and location context.
  4. Look for successful login after failures.
  5. Review audit logs and privileged changes.
  6. Correlate with endpoint / Defender telemetry where available.
  7. Assess user and business criticality.
  8. Document evidence and severity.

Response Actions

  • Revoke active sessions where justified.
  • Reset or rotate compromised credentials.
  • Require MFA re-registration when needed.
  • Block malicious IP / risky access path where appropriate.
  • Apply or tighten Conditional Access controls.
  • Review privileged role assignments and PIM activity.
  • Escalate confirmed compromise into incident response.
